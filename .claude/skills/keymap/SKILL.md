# /keymap: ショートカットの配置を相談する

KobitoKey（ZMK、40 キー、ドングルなし構成）にショートカットを置くための手順。提案までは編集せず、利用者が選んでから編集する。

## 用語

- ショートカット: Mac のアプリや OS が受け取るキー入力（例: Option+Esc）
- コンボ: 2 つ以上のキーの同時押しで別のキー入力を出す定義。有効にするレイヤーも決める
- レイヤー上のキー: 特定のレイヤーの 1 つのキーに置いたショートカット
- 配置先: コンボか、レイヤー上のキーのどちらか
- 配置替え: 置いたショートカットを別の配置先へ移すこと

利用者はキーの番号を覚えていない。キーは刻印や役割（H、J、Space、Enter）で呼び、レイヤーは機能（「マウスを操作するレイヤー」）、ラベル、番号のどれで言われても、keymap と照らして対象を決める。番号は内部で使い、利用者への説明では刻印で言う。

## 手順

1. 聞くこと: 置きたいショートカットと、使用頻度（1 日に使う回数の見積もり。実測ではない）。足りなければ聞く。
2. 現状を見る: `python3 .claude/skills/keymap/scripts/check_keymap.py` で、ベースレイヤーの刻印と既存のコンボを一覧する。レイヤーの内容は `config/KobitoKey.keymap` を読む。
3. 候補を 2〜3 個示す。各候補に、次の観点の理由を付ける。
   - 使用頻度に見合うか。頻繁に使うものほど押しやすい配置先にし、たまにしか使わないものは押しにくくてよい
   - 既存のコンボとの位置の重なり（同じ組み合わせ、または一方がもう一方を含む組み合わせは使えない）
   - レイヤーをまたいだ誤爆。コンボは `layers` を指定しないと全レイヤーで有効になる。他のレイヤーで同じ位置のキーを同時に押す操作があれば、誤爆する。その場合は `layers = <0>` のようにレイヤーを絞る
   - 押しやすさ（利用者が普段どの指でどのキーを押すか）
4. 利用者が選ぶまで keymap を編集しない。配置替えを提案するときも、どのショートカットを、なぜ移すかを示し、利用者が決める。使用頻度が低いものを動かす理由は薄い。
5. 選ばれたら keymap を編集する。コンボは `timeout-ms = <50>` を明示する。
6. 確かめる:
   - `python3 .claude/skills/keymap/scripts/check_keymap.py` で位置が重ならないこと
   - `python3 .claude/skills/keymap/scripts/check_keymap.py --has <コンボ名>` で定義があること
   - ビルドが通ること（`./docker-build.sh` は右側などを含めて全部作る。時間がかかるので、通常は次の flash.sh の中のビルドで確かめる）
7. `git diff` を見せ、OK をもらってからコミットする。OK の前にコミットしない。
8. `./flash.sh` で反映する。取り込みで止まったときは、自動で解決せず状況を知らせる。
9. 実機での動作確認は利用者が行う。出なかったときは 3 に戻って別の候補を選ぶ。

## このキーボードの特徴

- MOUSE レイヤー（layer 3）は、トラックボールを動かすと自動で入る。キーで入るレイヤーではない。この間はキー配置が MOUSE レイヤーのものになるので、レイヤー上のキーを置くときは考慮する
- キーで入るレイヤー: NUM&MOVE は右の Enter を長押し、SIMBLE は左の Minus を長押し、FUNCTION は右下の `]` を長押し
- キーマップとコンボは左側（セントラル）が持つ。書き込むのは左側だけ
- 既存のコンボは全レイヤーで有効。NUM&MOVE では H+J が ←↓、Y+U が数字の 6・7 にあたり、同時押しでコンボが出る
- combo_esc は Esc に続けて LANG2 を出す。単独の Esc が欲しいときは別の定義にする
